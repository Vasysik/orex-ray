# Обновление OrexRay через GitHub Releases

Источник обновлений: `https://api.github.com/repos/Vasysik/orex-ray/releases`.
Клиент выбирает наибольшую опубликованную (в том числе pre-release) версию с
файлами для текущей архитектуры и `SHA256SUMS.txt`.
Проверка выполняется после первого кадра приложения, вручную — «О приложении».
На главном экране появляется плашка, закрытие запоминается для конкретного тега.

Установщики должны иметь имена из `tool/build_release.ps1`:

- `OrexRay-<version>-arm64-v8a.apk`
- `OrexRay-<version>-armeabi-v7a.apk`
- `OrexRay-<version>-x86_64.apk`
- `OrexRay-<version>-x64-setup.exe`
- `SHA256SUMS.txt` (обязательно, в формате sha256sum).

Одинаковую версию только в локальном тесте можно показывать как обновление:

```powershell
flutter run --profile --dart-define=OREXRAY_UPDATE_TEST_SAME_VERSION=true
```

В штатной release-сборке этот флаг **не задавать**. Версию, которая старее
установленной, апдейтер не предложит даже в тестовом режиме. Для полноценной
проверки равных версий опубликуйте GitHub Release с тем же тегом, что и
текущая локальная сборка, с полным комплектом APK/EXE и `SHA256SUMS.txt`.
В обычной сборке равная и более старая версии обновлениями не считаются.

Android APK устанавливается через стандартный Package Installer, которому может
потребоваться разрешение «Установка неизвестных приложений». APK должен иметь
тот же package ID и signing key, а build versionCode не должен быть ниже
установленного. Debug package `ru.orex.ray.debug` — отдельное приложение; release
APK поверх него не установится. Windows запускает Inno Setup с UAC. Файлы
скачиваются целиком во временную папку, проверяются размер и SHA-256.

Клиент не может самостоятельно опубликовать релиз на GitHub. Этот процесс
остаётся отдельным шагом после сборки.
